# Lake Catch 产品定义

状态：MVP 和 V2 已完成；V3 进入 AI 实现上下文工作区阶段

日期：2026-10-28

## 1. 一句话定义

Lake Catch 是一个 macOS 本地Lake设计数据采集器：用户在应用内登录并打开Lake设计稿，点击同步后，应用通过Lake接口取得结构化设计 JSON，保存为可检查、可复用、可被 MCP 查询的本地设计资产。

## 2. 产品形态

产品由四部分组成：

1. **采集入口**：内置 WebView 负责登录Lake、打开设计稿和提供当前会话；后续可选接入 Chrome/Edge/Brave 扩展。扩展协议已预留，但当前版本不要求用户安装扩展。
2. **设计数据同步器**：通过Lake API 获取页面 JSON，解析图层、文字、样式、资源、切图和评论。
3. **本地图层检查器**：用户在本地查看完整图层树、滚动预览和节点详情，选择要实现的节点范围。
4. **MCP 桥接**：Codex 通过文档、node-id 或 DesignContext 查询结构化数据和资源。

产品不是：

- Lake网页的简单容器；
- 依赖 DOM 猜测规格的爬虫；
- 通过模拟鼠标点击逐个采集标注的自动化脚本；
- 把整页长图直接交给 Codex 的图片导入器；
- 自动生成完整业务代码的低代码平台。

## 3. 核心用户流程

```text
启动应用
  -> 登录Lake并打开设计稿
  -> 点击同步当前页面
  -> 查看 API/JSON 采集进度
  -> 在本地图层树选择节点
  -> 创建 DesignContext
  -> Codex 通过 MCP 读取并实现
```

“同步整页”是一次性获取该设计页的结构化图层树。用户不需要先在Lake里选中每一个内部元素；本地检查器负责后续节点选择。

## 4. 同步结果状态

| 状态 | 含义 | 是否可供 Codex 实现 |
|---|---|---|
| `confirmed` | 来自Lake JSON 并完成字段映射 | 可以 |
| `partial` | 拿到部分响应或部分字段 | 可以，但必须显示缺失项 |
| `candidate` | DOM/页面诊断/启发式结果 | 不可作为确定规格 |
| `unknown` | 尚未知道字段含义 | 不可假设 |
| `failed` | 采集阶段失败 | 不可使用 |

同步界面必须显示失败发生在哪个阶段：路由解析、凭据读取、API 请求、JSON 下载、JSON 解析、资源下载或本地保存。

## 5. MVP 范围

### 必须完成

- 内置 WebView 登录和当前Lake链接识别；
- 单页 API 请求和 `json_url` 下载；
- `artboard.layers` 递归解析；
- frame、文字、基础样式、资源和评论的统一映射；
- 本地文档保存和版本；
- 图层树、长页面滚动预览和节点详情；
- DesignContext 创建；
- MCP 只读查询；
- 凭据不落盘、错误可解释。

### MVP 不做

- Lake设计稿编辑和回写；
- 云端同步和团队协作；
- 多设计平台；
- 完全自动代码生成；
- 复杂动画和交互状态还原；
- 默认安装浏览器扩展；
- 当前版本强制要求浏览器扩展或 Apple Developer 账号；
- 用长图替代结构化图层数据。

## 6. 成功标准

一个真实的、有权限的Lake设计页可以完成以下闭环：

1. 用户在应用内登录并打开页面。
2. 点击一次同步后得到清晰的成功或失败结果。
3. 成功时本地保存真实图层树、文字和可用资源引用。
4. 用户关闭应用后仍可打开同步结果。
5. 用户在本地选择一个内部节点生成 context。
6. Codex 通过 MCP 读取 context，且不会把 `candidate` 字段误当成确认规格。

## 7. V2 产品形态

V2 不改变 Lake Catch 的核心职责，而是把“本地图层检查器”升级为可交互的设计检查工作台：

- 在本地画布中按真实节点坐标渲染设计稿；
- 支持缩放、平移、滚动和画布适配；
- 点击画布中的图层即可选中对应节点；
- 重叠图层支持逐层选择；
- 选中节点后显示尺寸、位置、文字、样式、资源和来源定位；
- 从当前节点直接创建 DesignContext；
- 复制设计稿链接、`lake://design-node/{documentId}/{nodeId}` 节点定位链接和当前上下文信息；
- 预览、筛选和导出可用于 Android `res/drawable` / `res/mipmap` 的资源；
- MCP 可以直接读取当前文档、当前选中节点或当前上下文。

V2 仍然不负责：

- 读取或还原设计工具之外的业务交互流程；
- 解析动画时间线、手势和完整原型状态机；
- 编辑或回写 Lake 设计稿；
- 在 Lake Catch 内置 Android、iOS、Web 代码生成器。

## 8. V2 成功标准

1. 同步后的真实设计稿可以在本地画布中按节点坐标查看。
2. 用户点击画布中的任意可确认图层，可以定位到对应节点并查看详情。
3. 重叠图层不会只能选到最上层，用户可以继续选择被遮挡的图层。
4. 用户可以从当前选中节点创建 context，并在 MCP 中直接读取该节点及其子树。
5. 用户复制的节点定位信息在重新打开应用或交给 Codex 后仍能定位到同一文档和节点；MCP 可以通过对应资源模板读取节点详情，也可以直接读取应用当前选中的节点。
6. 资源列表能够明确区分可用、远程引用、跳过密度和待复核资源，并支持 Android 目录建议。
7. 现有第一版的同步、存储和 MCP 全部回归通过，不因画布功能引入设计稿专属固定逻辑。

## 9. V3 产品方向：补齐 DesignBridge 差异

V3 不把“选中区域后是否再次同步”当作新需求。当前行为保持不变：同步仍然获取整张设计稿，选中节点只决定后续查看和 MCP 查询范围。

V3 的目标是补齐 Lake Catch 与 DesignBridge 在交付体验上的差距：让用户更容易把某个设计区域、它的来源、标注和资源交给 AI 使用。

### 9.1 主要差异

当前 Lake Catch 已具备：

- 通过内置 WebView 登录并同步结构化设计 JSON；
- 本地画布、图层树、节点详情和重叠节点选择；
- `lake://design-node` 定位链接、DesignContext 和当前选择 MCP 查询；
- 资源缓存、密度判断和 Android 目录建议；
- 独立 MCP server 和正式 `.app` 交付。

仍需要补齐或加强：

- 选中节点后的一键交付入口，减少复制 ID 和理解 MCP 工具名的需要；
- 更完整的标注/评论数据模型和 MCP 输出；
- 针对当前选区的切图清单与导出检查，而不是只在整页资源列表中展示；
- 设计稿、节点、上下文和同步版本之间更稳定的来源链路；
- 面向不同 AI 工具的安装、检测和故障提示；
- DesignBridge 的浏览器扩展和跨浏览器采集能力暂列为可选差异，不作为 Lake Catch V3 的前置条件。

### 9.2 V3 用户流程

```text
打开设计稿
  -> 同步整张设计稿（只做一次）
  -> 在 Lake Catch 画布中选中区域
  -> 点击“交给 AI”或复制节点定位
  -> AI 通过 MCP 获取节点、标注和关联资源
  -> 用户在 AI 工具中指定 Android、iOS、Web 等目标平台
```

### 9.3 V3 产品能力

1. **节点交付入口**
   - 对当前选中节点提供一个明确的“交给 AI”操作；
   - 自动生成包含文档、版本、节点和上下文范围的 MCP 定位信息；
   - 用户不需要手动复制多个 ID，也不需要记忆工具名称；
   - 未选中节点时明确提示应先选择图层，而不是静默返回整页。

2. **标注和评论补齐**
   - 保留设计数据中的标注、尺寸、颜色、字体、间距和评论来源；
   - 区分设计 JSON 的确认字段与页面诊断候选；
   - MCP 查询节点时同时返回与该节点相关的标注和评论。

3. **选区资源交付**
   - 第一阶段继续使用当前整页资源列表，不增加按选区筛选资源；
   - 给出 `res/drawable` 或 `res/mipmap` 建议；
   - 继续跳过明确的 `mdpi` / `hdpi` 变体；
   - 对未知密度、缺少 URL、下载失败和缓存缺失给出处理原因；
   - 第一阶段只提供清单和 MCP 数据，是否写入外部项目另行确认；选区资源过滤列入后续评估。

4. **来源链路和版本一致性**
   - 每个节点交付结果都带有设计稿、同步版本、节点和来源 URL；
   - 重新同步后能识别旧定位是否仍然有效；
   - 历史版本和当前版本不会混用。

5. **MCP 安装和诊断体验**
   - 提供一次点击的安装/修复/检测入口；
   - 配置不依赖开发机路径，适用于发给其他用户的 `.app`；
   - 明确显示“配置已写入”“进程可启动”“AI 工具已连接”三个状态。

### 9.4 V3 不做

- 不把局部选中变成第二次同步；
- 不在 Lake Catch 内置 Android、iOS、React、Compose 或 SwiftUI 代码生成器；
- 不直接修改用户的业务项目目录；
- 不把整页长图当作实现结果或唯一资源来源；
- 不通过模拟点击逐个图层来代替结构化数据同步；
- 不把 candidate 或 unknown 数据提升为 confirmed；
- 不把浏览器扩展、Native Messaging、设计稿编辑和云端协作作为 V3 前置条件。

## 10. V3 成功标准

1. 用户同步整页后，只需在 Lake Catch 中选中节点并点击一次交付入口，AI 就能获取正确的节点范围。
2. AI 获取的数据包含节点结构、已确认标注和来源定位；资源仍按当前整页资源清单提供。
3. 任何不确定、缺失、截断或过期信息都会明确显示，不会被包装成完整规格。
4. MCP 配置在另一台安装了 `Lake Catch.app` 的 macOS 上也能自检和启动，不依赖开发机路径。
5. 用户仍可以让不同 AI 工具生成不同平台代码，Lake Catch 不承担平台代码生成职责；选区级资源过滤不作为 V3 首批要求。
